# C Binding

The C API is the primary interface. It is generated by cbindgen from the
Rust FFI layer in `src/ffi/` and declared in `renoir.h`.

## Header

Build with the `c-api` feature:

```sh
cargo build --release --features c-api
```

The header is written to `include/renoir.h` (and
`target/include/renoir.h`). Link against `target/release/librenoir.so`.

## Core types

- Handles are opaque pointers: `RenoirTopicManagerHandle`,
  `RenoirPublisherHandle`, `RenoirSubscriberHandle`,
  `RenoirManagerHandle`, `RenoirRegionHandle`,
  `RenoirBufferPoolHandle`, ...
- `RenoirErrorCode` variants are prefixed with the enum name to avoid
  global-namespace collisions: `RenoirErrorCode_Success`,
  `RenoirErrorCode_BufferFull`, ...

## Topic lifecycle

```c
RenoirTopicManagerHandle mgr = renoir_topic_manager_create();

RenoirTopicOptions opts = {0};
opts.pattern = 0;                 /* SPSC */
opts.ring_capacity = 16;
opts.max_payload_size = 4096;

RenoirTopicId tid;
renoir_topic_register(mgr, "/sensor/imu", &opts, &tid);

RenoirPublisherHandle pub;
renoir_publisher_create(mgr, "/sensor/imu", NULL, &pub);

RenoirSubscriberHandle sub;
renoir_subscriber_create(mgr, "/sensor/imu", NULL, &sub);

renoir_publish(pub, data, len, NULL, &seq);

RenoirReceivedMessage msg;
if (renoir_subscribe_read_next(sub, &msg, 1000) == RenoirErrorCode_Success) {
    /* msg.payload_ptr, msg.payload_len */
    renoir_message_release(msg.handle);
}

renoir_publisher_destroy(pub);
renoir_subscriber_destroy(sub);
renoir_topic_manager_destroy(mgr);
```

## Statistics

`renoir_topic_stats`, `renoir_publisher_stats`, and
`renoir_subscriber_stats` fill a `RenoirTopicStats` with real values:
message counts, average/peak end-to-end latency in ns, and cumulative
throughput in Mbps.

`renoir_region_stats` reports total/used/free bytes. `fragmentation_ratio`
is `-1.0` when not available for the allocator type (fixed-block pool /
bump) — the sentinel is documented on the struct.

## Concurrency

All operations are thread-safe. Topics with single-writer or
single-reader patterns (SPSC/SPMC/MPSC) enforce their constraint
atomically; duplicate registration with conflicting configuration is
rejected.
